AXM SHAPEABLE BUILDER v0.13 BETA
================================

FASTEST START ON WINDOWS

1. Unzip the package.
2. Double-click START_BUILDER_WINDOWS.bat

You can also double-click index.html directly.
For the full installable/offline-app mode, see “Start it” in README.md.

BEGINNER: PLACE AND MOVE BLOCKS

1. Choose a layer.
2. Drag a library block onto the canvas. Touch and pen dragging work too.
3. Follow the landing preview, then release to place.
4. Drag a placed block by its header to move it.
5. Blocks gently snap to a 12-pixel grid and nearby alignment lines.
6. Hold Shift during a mouse drag for free placement.
7. The canvas scrolls when you hold a dragged block near an edge.
8. One completed drag is one Undo/Redo step. A cancelled drag changes nothing.

The + button still adds a block to the visible center when dragging is inconvenient.
Keyboard: focus a placed block and use Arrow keys; Shift + Arrow moves one pixel.

BEGINNER: SHAPE ONE PLACED BLOCK

1. Open a starter or place a block.
2. Select that block on the canvas.
3. Find “Per-block influence” in the Inspector.
4. Add a reaction by choosing WHEN, DO and DETAIL.
5. Use Preview to read what the reaction would do without changing source.
6. Open Visual states only when that one block needs different appearances.
7. Leave Advanced code hook drafts closed unless you deliberately need them.

A palette block is the reusable type. A canvas block is one specific copy.
Changes in “Per-block influence” belong to that selected copy.

Visual-state asset requests are local JSON packets only. They do not contact a generator, upload an image or apply a result.

Advanced code drafts are visible source only. They are marked “Saved, not run,” cannot be enabled in this beta and are excluded from standalone builds.

HUMAN + YOUNG AI SHARED BUILDER

The “AI seat” opens the Young AI Workbench.

1. Open a project and set the human goal.
2. Open AI seat.
3. Export or copy the local workspace packet.
4. Give it to the AI system you deliberately choose.
5. Bring the returned axm.agent.proposal JSON back to the Workbench.
6. Validate and dry-run it.
7. Review every action, then apply, revise or reject.
8. Test the actual changed path. A valid proposal is not proof that it works.

The builder does not include or secretly contact an AI provider. The young AI seat is PROPOSE ONLY. It cannot directly grant permissions, enable code, alter canon, erase projects, publish, make network calls or execute an outside engine. An accepted proposal becomes one undoable candidate source change and receives a human review receipt.

LOCAL SOURCE TRUTH

Your project vault is stored only in that browser on that device. Use “Build & export” to download portable AXM project JSON for important work. Checkpoint restores and imported projects receive separate identities instead of silently overwriting active source.

AI, asset generation, LAN, local multiplayer, phone-controller, external-state and External Engine Dock paths marked contract-only beta do not pretend an outside runtime is connected. Their downloads are local contracts only: they do not send, apply or execute anything by themselves.
