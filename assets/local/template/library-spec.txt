============================================================
CORE DISCOVERY
============================================================

The template system is not only for speed or style.
It is a stability layer for human + AI creation.

Core rule:

    STABLE SHELL. FLEXIBLE SLOTS. PROTECTED OUTPUT.

Or in Mike's words:

    Outer stable. Inner transparent / flexible.

This is the same pattern already tested in AXM profile picture templates,
faction templates, and now the AXM Hub comic prototype.

The important upgrade is realizing that templates are not just visual helpers.
They are guardrails for quality, continuity, professionalism, and AI drift control.

============================================================
WHY THIS MATTERS
============================================================

The AXM Hub comic test showed that AI can generate strong visual pages,
but without a locked shell it can drift in boring production details:

- page sizes can change
- borders can change
- page numbering can drift
- signatures can move
- filenames can become inconsistent
- output format can vary
- style can slowly shift
- character continuity can weaken
- one-page requests can become spreads

These are not creativity problems.
They are structure problems.

The Hub can solve this by keeping the reusable outer structure locked,
while letting humans and AI fill the inner content freely.

This lets AI focus on what it does best:

- ideas
- composition
- wording
- visual content
- adaptation
- iteration
- scene design
- explanation

And it stops AI from needing to remember every boring format rule manually.

============================================================
MAIN TEMPLATE PRINCIPLE
============================================================

A professional AXM template should have two major layers:

1. OUTER STABLE SHELL
2. INNER FLEXIBLE / TRANSPARENT CONTENT

The shell protects continuity.
The inside protects creativity.

------------------------------------------------------------
OUTER STABLE SHELL
------------------------------------------------------------

The outer shell should stay locked unless intentionally edited.

It can include:

- canvas size
- border
- safe margins
- title zone
- subtitle zone
- page number position
- footer
- signature area
- AXM mark / symbol zone
- color system
- typography rules
- export size
- export format
- naming rules
- versioning rules
- style constraints
- readability constraints

Example signature lock:

    Mike - Axiom/Mir

------------------------------------------------------------
INNER FLEXIBLE / TRANSPARENT CONTENT
------------------------------------------------------------

The inside of the template stays open and adaptable.

It can include:

- panel art
- captions
- speech bubbles
- faction art
- unit identity
- lore
- symbols
- icons
- diagrams
- screenshots
- steps
- statistics
- feature notes
- roadmap content
- scene content
- character placement
- experimental variants

The inner content can change without breaking the page's professional structure.

============================================================
CONNECTION TO EARLIER AXM TESTS
============================================================

------------------------------------------------------------
1. PROFILE PICTURE TEMPLATE TESTS
------------------------------------------------------------

The large profile picture template tests were basically drift tests.

They asked:

- Can one template produce many different outputs?
- Can identity survive variation?
- Can the system stay recognizable across many generations?

At the time, the focus was mostly variation and identity.
The new insight adds professional stability.

Now the test becomes:

- Can it vary?
- Can it keep identity?
- Can it keep format?
- Can it be product-quality without manual rescue?

------------------------------------------------------------
2. FACTION TEMPLATE TESTS
------------------------------------------------------------

The faction system already followed the same pattern.

Outer stable:

- faction card frame
- name zone
- role/stat zones
- icon positions
- export size
- AXM mark
- readability rules

Inner flexible:

- faction art
- colors
- units
- lore
- mechanics
- symbols
- experimental versions

The faction system proved that a stable outer identity can support many different inner worlds.

------------------------------------------------------------
3. AXM HUB COMIC TEST
------------------------------------------------------------

The comic proved the missing professional layer.

When every page was generated from scratch, the content was often strong,
but the outer production structure could drift.

The final four pages came out smaller/square compared to the earlier portrait pages.
That became a practical signal:

AI needs a locked page shell for professional consistency.

The repaired normalized zip fixed the size afterward,
but the better future solution is to prevent the drift at template level.

============================================================
THREE TEMPLATE ASSET LAYERS
============================================================

Professional templates should be made from three reusable asset layers.

------------------------------------------------------------
A. SHELLS
------------------------------------------------------------

Full-page frame / style shell.

Examples:

- AXM Comic Base Shell
- AXM Info Page Shell
- AXM Faction Card Shell
- AXM Social Post Shell
- AXM Log Sheet Shell

The shell protects page size, border, signature, margins, and basic identity.

------------------------------------------------------------
B. LAYOUTS
------------------------------------------------------------

Panel or block arrangement inside the shell.

Examples:

- 4-panel page
- 5-panel page
- 6-block infographic
- split comparison
- top-wide panel + bottom panels
- cover layout
- back cover layout
- character reveal layout
- timeline layout

Layouts can be swapped while the shell stays stable.

------------------------------------------------------------
C. BLOCKS
------------------------------------------------------------

Small reusable components.

Examples:

- speech bubble
- caption box
- quote box
- warning box
- status card
- page tag
- character label
- icon slot
- stat block
- source note
- signature block
- checkpoint marker

Blocks help beginners build professional-looking pages without designing every part manually.

============================================================
TEMPLATE INHERITANCE
============================================================

The template system should support inheritance.

Example:

Base template:

    AXM Comic Base

Contains:

- page size
- border
- footer
- signature
- safe margins
- style rules

Child templates:

- AXM Comic 4-Panel
- AXM Comic 5-Panel
- AXM Comic Cover
- AXM Comic Back Cover
- AXM Comic Infographic Page
- AXM Comic Character Reveal

If the base border or footer improves later, child templates can inherit the improvement.

This avoids manually updating every template one by one.

============================================================
FRONTEND BEHAVIOR
============================================================

What the user sees should be beginner-friendly.

Possible workflow:

1. Pick a template family
2. Pick a template
3. Fill title
4. Fill text slots
5. Add images or ask AI to generate/fill them
6. Preview
7. Fix warnings
8. Export

Example user-facing command:

    Use AXM Comic 5-panel template.
    Page 18.
    Title: Multi-AI Role Routing.
    Use Founder Mike.
    Keep signature: Mike - Axiom/Mir.
    Export as portrait PNG.

The user should not need to manually remember canvas size, margins, footer rules, or export naming.

============================================================
BACKEND / RULE LAYER
============================================================

Behind the frontend, the Hub should enforce boring production rules.

Possible rules:

- keep all pages same size
- keep footer in same place
- keep page numbering correct
- keep signature position stable
- warn if image ratio is wrong
- warn if text overflows
- warn if safe margin is broken
- warn if export filename is wrong
- warn if page order is missing
- warn if a page has the wrong template type
- warn if character reference is missing
- warn if output becomes a spread instead of a single page
- preserve transparent areas where needed
- keep source/template metadata attached

This is where the Hub becomes AI-native and technical by default.

============================================================
AI FILL MODE
============================================================

In the future Hub, AI should not always generate the whole design from nothing.

Better mode:

- template already exists
- slots already exist
- rules already exist
- AI fills only the selected content areas

Example:

Template:

    AXM Info Comic Page 01

Locked:

- border
- title bar
- footer
- page number
- signature
- export size

Open slots:

- Panel 1 image
- Panel 1 caption
- Panel 2 image
- Panel 2 caption
- Big quote box
- Bottom action note

AI task:

    Fill the inner slots using this topic while preserving the shell.

This reduces drift because the AI is not asked to recreate the entire product frame.

============================================================
QUALITY TESTS
============================================================

Each professional template should pass four tests.

------------------------------------------------------------
1. VARIATION TEST
------------------------------------------------------------

Can the template produce many different outputs without becoming boring?

------------------------------------------------------------
2. IDENTITY TEST
------------------------------------------------------------

Does every output still feel like it belongs to the same system?

------------------------------------------------------------
3. STABILITY TEST
------------------------------------------------------------

Does the frame, size, naming, signature, page order, and export stay locked?

------------------------------------------------------------
4. PROFESSIONAL TEST
------------------------------------------------------------

Could the output become a clean product without manually fixing every page?

============================================================
SHORT AXM RULES
============================================================

1. The shell protects continuity.
2. The inside protects creativity.
3. Templates are drift-control tools, not only design shortcuts.
4. AI should fill slots, not rebuild the whole product frame every time.
5. Stable defaults make flexible work safer.
6. Professional output needs boring structure.
7. Inner content may evolve; outer structure must protect continuity.
8. Reusable templates should support comics, factions, info pages, social posts, logs, and future AXM tools.

ONE-LINE SUMMARY
============================================================

AXM templates should use stable outer shells with transparent flexible inner slots, so humans and AI can create professional comics, info pages, factions, social posts, and workflow logs without losing size, structure, identity, or continuity.
