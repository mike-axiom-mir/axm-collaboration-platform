# UI Sensory Capability Scout

The old missing-hand catalog was empty, but live diagnosis exposed a real gap.
ui-component@1.1.0 created a READY/PASS static SVG and runtime metadata while
declaring editable output and an editable recipe format. It emitted no recipe
artifact, rejected operation_mode edit, and offered only a static preview for
four declared states and nine-slice readiness.

Three candidates were compared with the collaborating machine task:

1. UI component edit plus stateful prototype: selected. It combined a genuine
   machine edit/recipe gap with a bounded human browser journey.
2. Pixel sprite round-trip and real raster delivery: valuable, but overlapped
   more existing pixel tooling and had an additional source bridge to design.
3. Collision/navigation path query: genuine gameplay gap, but runtime traversal
   evidence is less bounded and more dependent on target-engine semantics.

The selected machine lane upgraded ui-component to 1.2.0, registered an exact
recipe, and added deterministic-ui-fabric. This human lane closes the bounded
host and browser observation seats at TEST. Physical input, assistive tech,
native runtime parity, performance and human taste remain open.
