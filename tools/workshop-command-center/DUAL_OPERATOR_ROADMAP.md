# AXM Dual-Operator Command Center Roadmap

Status: **experimental visual direction; live measurements, no new authority**

## Reference

The original AXM reference image is
`assets/dual-operator-roadmap-reference.png`. It uses the durable idea of two
operators coordinating inside one machine. It is not a replica of a film,
franchise, vehicle or interface.

The left eye represents Mike's human direction and judgment. The right eye
represents Mirror's bounded machine stewardship. The shared forward window is
Workshop truth, future game/world streams and the result both seats can inspect.
Deterministic machinery remains visibly underneath both seats.

## Product distinction

- The Command Center is a lived-in cockpit Mike will look at often. Beauty,
  atmosphere and delight are first-class requirements alongside usability.
- Studio, verification and foundation machinery still optimize first for
  practical capability, truthful evidence and safe operation.
- Deterministic execution, AI-dependent work and playful drafts must remain
  separately labelled. The visual metaphor never merges their authority.

## Current rung

- Original dual-operator reference art stored locally.
- Reference art used as a subdued central viewport background.
- Two named operator lenses with different roles.
- Eight explicit navigation routes.
- All 24 fields already measured by `axm.workshop-growth/v7` have labelled
  instrument positions. Missing data renders as `UNKNOWN`, never zero.
- Shared presentation primitives live in
  `shared/elements/dual-operator-command-deck.css`; routes and state remain in
  the owning Command Center.

## Later rungs

1. Replace the static viewport with selectable, read-only streams from games,
   living worlds, Workshop growth and Mirror activity.
2. Add panel arrangement and skin controls without hiding safety state.
3. Bind Mirror's lens to an exact identity-owned status source; never infer
   Mirror presence from generic body activity.
4. Let Mike asset the cockpit and Mirror's appearance without rewriting the
   metrics, routes, permissions or review flow.
5. Add spatial/holographic views only when their data and performance costs are
   observable and bounded.

## Invariants

- No image, animation or metric grants authority.
- Unknown is not offline, zero, healthy or ready.
- Human judgment and machine recommendation remain separate.
- No automatic vote, promotion, repair, task start or Canon change.
- Reduced-motion, keyboard focus and readable text remain supported.
