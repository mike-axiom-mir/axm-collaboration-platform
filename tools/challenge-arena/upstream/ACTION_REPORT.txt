AXM CHALLENGE ARENA v0.6.0 — ACTION REPORT
============================================
Date: 2026-08-16
Rollback root: v0.5 remains unchanged and should be retained with its matching release archive.

WHY THIS ROUND WAS WORTH DOING
------------------------------
The v0.6 failure-first audit found two material classes of defect in v0.5:

1. Evidence-bundle portability false negative.
   The standalone verifier parsed canonical event files in sorted filename order,
   but later compared expected event filenames against the ZIP archive's original
   member order. The same valid evidence bytes could therefore verify or fail only
   because a ZIP writer stored members in a different order.

2. Observer confidentiality was route-local rather than observer-wide.
   The main challenge view protected blind identities, but /api/progress could
   expose real submitter/reviewer IDs; detailed integrity or lineage material
   could also carry identity-bearing forensic data; and an HTTP exception could
   echo raw internal exception text.

These are exactly the kinds of defects a local interchange module should repair:
one concerns transport representation being mistaken for evidence semantics; the
other concerns privacy holding on the normal screen but leaking through side
routes or failure paths.

WHAT CHANGED
------------
- Canonical event verification is independent of ZIP member ordering.
- A deterministic bundle-portability audit tool can repack identical evidence in
  randomized member orders and verify every repack.
- /api/progress now returns aggregate/count-only public progress.
- /api/integrity now returns a public-safe integrity summary; forensic errors stay
  available through the local Python/CLI interface.
- /api/lineage now exposes public topology/counts without copied participant IDs,
  operator IDs, selected blind labels, or detailed lineage input paths.
- Observer HTTP failures return a generic public-safe error instead of raw
  exception text.
- Observer responses add Cross-Origin-Resource-Policy, Cross-Origin-Opener-Policy,
  and X-Permitted-Cross-Domain-Policies hardening.
- v0.5 challenge wire semantics are preserved. v0.6 does not fabricate a new
  challenge contract simply for release branding.
- v0.5 remains a separate rollback release; it was not overwritten.
