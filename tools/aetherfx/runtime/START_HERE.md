# Start Here — AXM AetherFX v1.3.0

This verified stewardship release hardens contract truth, import safety, runtime reuse, and adapter reporting without inflating the 64-module catalog. The next useful work is real AXM product integration rather than another volume-only effect pass.

## Fastest route

1. Extract the complete ZIP.
2. Open `OPEN_STUDIO.html`.
3. Press **Guide** and describe the outcome in simple controls.
4. Inspect the generated Active Stack and Dependency Graph.
5. Tune only what matters, then validate and export.

## Best first proof

Use **Guide** to create a luminous product surface with a calm or cinematic mood. Open **Performance** to see the estimated load and largest contributors. Open **Graph** to inspect what the simple surface is made from. Then create a composite with promoted controls and reuse it as one layer.

## Safety and recovery

- Raw recipes are validated in their submitted form; normalization changes are shown before confirmation.
- **Import Review** checks required SHA-256 integrity, cycles, bounds, dependencies, collisions, and licence notices before the live registry is changed.
- Package import is transactional: a failed package does not leave earlier modules installed.
- **Repair** analyses broken recipes and proposes bounded fixes.
- **Photosensitive safe** suppresses repeating sweeps and rapid decorative motion without flattening the layout.
- `Auto` quality can adapt at runtime without rewriting the saved recipe.
- Snapshots now preserve the recipe and custom module definitions together; undo/redo and file export remain separate recovery routes.

## Reuse outside the Studio

- `dist/runtime/axm-aether-runtime.mjs` and `.js` expose validation, compilation, intent, support reporting, transactional package import, and full snapshots.
- `tools/axmfx-cli.mjs` validates, compiles, or inspects a recipe or sealed package.
- `integration/runtime/example.mjs` is the smallest executable proof of the portable runtime path.
