AXM Hermes Runtime Adapter - local start note

External Hermes stays pinned and reviewable. The AXM runtime policy and the older loopback proposal service are separate layers.

Pinned runtime path (explicit commands only):

cd AXM_WORKSHOP\tools\hermes
node hermes-bootstrap.js doctor
node hermes-bootstrap.js install
node hermes-bootstrap.js verify
node hermes-bootstrap.js deps
node hermes-bootstrap.js prepare

Action consent starts OFF.

To deliberately permit policy-approved Hermes tool calls:

node hermes-bootstrap.js consent on "local reviewed run"

Start pinned Hermes through the AXM profile:

node hermes-bootstrap.js start

To revoke action consent:

node hermes-bootstrap.js consent off "run ended"

Important:
- the source checkout must match hermes-source.lock.json exactly
- high-authority terminal/code/computer/delegation/scheduling/messaging capabilities remain OFF unless local policy explicitly changes them
- the AXM hook is an authorization gate, not an OS sandbox
- model-provider network egress is a separate boundary
- Hermes memory, generated skills, and conclusions are not AXM canon

Optional legacy AXM proposal/control-layer test:

cd AXM_WORKSHOP\tools\hermes
node hermes-runner.js

Then check:

http://127.0.0.1:8791/health

The legacy loopback consent store gates that service's write routes only. It is not yet unified with runtime/policy.json.
