AXM Hermes Runtime Adapter

Pinned upstream Hermes Agent, launched through an AXM-owned profile with explicit action consent, fail-closed pre-tool policy, and redacted receipts.

What exists now

  • Immutable reviewed upstream source lock with origin + SHA verification
  • Separate explicit source, dependency, profile-preparation, consent, and start steps
  • Fail-closed AXM policy before Hermes tool execution
  • High-authority terminal/code/computer/delegation/scheduling/messaging OFF by default
  • Metadata-only tool receipts; Hermes output, memory, and skills remain non-canonical
  • Existing loopback proposal service remains available as a separate local layer

Boundary

The AXM tool gate is real authorization, not an OS sandbox. It does not by itself contain a local shell and it does not gate model-provider network egress. Use genuine Docker/VM isolation before enabling host-capable execution.
The legacy loopback consent store and the runtime policy consent store remain separate until deliberately unified.
