AXM external runtime adapter

Hermes — bounded power, repairable runs

Pinned Hermes Agent with AXM research/operator postures, credential egress filtering, fail-closed tool authority, per-run evidence capsules, and candidate-only Return Packets.

Default

  • Research posture — narrow read/research allowlist
  • Consent OFF — runtime can exist without tool authority
  • Provider credentials local-only — inherited secrets stripped before child launch
  • Mutation/world actions OFF — file writes, terminal, code, browser action, messaging, memory/skill mutation, delegation, scheduling and generation are separate switches

Every launch

  • Verifies official source + commit + Git tree + package version
  • Creates a fresh run capsule with independent counters
  • Records hashed metadata-only tool/provider/session receipts
  • Emits a non-canonical Return Packet on exit
  • repair closes orphaned interrupted capsules instead of deleting evidence

Boundary

Tool authorization is not an OS sandbox. Credential filtering is not hard network isolation. Provider observer receipts can expose a policy mismatch but cannot veto an already-dispatched provider request. Use Docker/VM/network isolation when those guarantees matter.
Hermes memory, generated skills, results, and Return Packets remain candidate material. Legacy loopback consent is still separate from runtime policy.
