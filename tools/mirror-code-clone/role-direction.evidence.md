# Code Mirror role-direction evidence route

Recorded 2026-07-27. This record supersedes the interpretation that the v0.2
repair prototype is the intended future Code Mirror. It does not erase the
prototype or its candidate receipts.

## repairbuddy-owns-repair

- claim: RepairBuddy is the stability-oriented bounded repair-pattern body.
- kind: static structure and human role judgment
- risk: medium
- pass condition: Mike's direction names RepairBuddy for repair, while the
  installed RepairBuddy declarations describe verified repair-pattern replay
  and refuse free code generation and automatic repair application.
- primary surface: `role-direction-v1.json`, RepairBuddy manifest and contract.
- counterevidence: RepairBuddy claims an innovation role or accepts arbitrary
  new-code generation.
- secondary surface: `node tools/repairbuddy/selftest.js`.
- observed evidence: the role-direction test passed 10/10 and RepairBuddy
  passed 62/62 checks.
- verdict: PASS.
- named seam: future repair evidence may still need explicit human pattern
  admission; role ownership grants no automatic repair authority.

## current-v02-is-repair-prototype

- claim: `mirror-code-clone` v0.2 implements repair, not innovation.
- kind: deterministic behavior and static structure
- risk: medium
- pass condition: its only transforms are allowlisted manifest repair classes;
  no novelty or innovation procedure is present.
- primary surface: kernel, manifest, contract, and 14 preserved receipts.
- counterevidence: an innovation proposal contract, novelty evaluator, or
  non-repair candidate path exists in v0.2.
- secondary surface: `node tools/mirror-code-clone/selftest.js`.
- observed evidence: the historical self-test passed 18/18; all 14 current
  receipts are repair candidates for one manifest-completeness class.
- verdict: PASS.
- named seam: the v0.2 name and UI still say Code Clone, so the role mismatch is
  preserved and labelled rather than silently rewritten.

  repair-receipt lesson lane is disabled, and no such lesson is admitted.
- primary surface: live Heartbeat lane status plus Mirror private episode
  inventory.
- counterevidence: the lane is enabled, an admitted lesson names
  `dual-reviewed-candidate-lesson`, or a repair receipt is cited as innovation
  improvement.

  self-test.

  `trainingAuthority:NONE`; all 14 review items remain `PENDING`; Mirror has zero
  Workshop action-feed lessons and its runtime is offline.
- verdict: PASS.
- named seam: Mirror's general private learning systems are separate; this
  verdict applies only to the Code Clone repair-receipt lane.

## future-code-mirror-capability-story-body

- claim: a Code Mirror capable of originating bounded capability-bearing code
  stories has been built and shown to improve.
- kind: existence and learning improvement
- risk: high
- pass condition: a disposable proposal-only body converts an attributed story
  brief into a coherent human story view and a working machine capability view
  of the same trace, then beats a declared baseline on independently authored
  held-out capability behavior, story-coherence, novelty, and usefulness cases
  without regression or authority gain.
- primary surface: absent innovation contract/body and absent held-out exam.
- counterevidence: none; the required artifacts do not exist.
- secondary surface: no learned innovation corpus or model is present.
- observed evidence: direction only; body, corpus, examiner, and improvement
  receipt are all absent.
- verdict: FAIL_NOT_BUILT.
- named seam: story guides creative proposals but cannot grant truth,
  permission, evidence, release, or CANON authority. Coherence, novelty, and
  usefulness require an independent evaluator and Mike's judgment; working
  capability requires executable behavioral evidence. Source difference alone
  cannot prove innovation.
