# Four-phone LAN qualification capability contract

```text
capability_id: qa.four-phone-lan.session-recorder
purpose: Produce a compact qualification receipt for a four-controller Mirrorshift session on the intended local router while preserving the separate human/physical-device verdict.
inputs and schemas: Opt-in `?lanlab=1` host route; `axm.mirrorshift-telemetry/v1`; per-session `axm.mirrorshift-transport-telemetry/v1`; privacy-bounded `axm.four-phone-lan-preflight/v1`; per-controller `axm.mirrorshift-seat-confirmation/v1`; host attestations for four independent physical phones, intended router/LAN, and visible seat identity; 2, 10, or 30 minute duration.
outputs and schemas: Downloadable `axm.four-phone-lan-qualification/v1` receipt with the sanitized start preflight, per-seat connected and confirmed counts, controller-session stability, applied meaningful drive, item attempts, heartbeat, resume, per-session RTT, simultaneous four-seat coverage, input-ownership protection, bounded transitions, review eligibility, and explicit physical-verdict boundary.
side effects: One controller-local seat-confirmation POST plus read-only local telemetry GETs, bounded in-memory aggregation, and a user-initiated local JSON download. Confirmation updates session metadata only. The lab creates no controller sessions, sends no gameplay actions, changes no authority, and performs no external upload.
permissions and consent: LAN Lab is hidden unless `?lanlab=1`; every controller starts unconfirmed and must explicitly tap `CONFIRM P1` through `CONFIRM P4` in the lobby; recording begins only after START QUALIFICATION or explicit `lanAutostart=1`; host attestations are separate explicit unchecked controls and are retained only as booleans.
resource budget: One-second telemetry polling; at most 128 transitions; aggregate counters only; no raw action/session log; hard 30-minute ceiling.
failure and recovery behavior: START remains disabled until telemetry is healthy and P1-P4 each have exactly one controller session that is currently connected and explicitly confirmed. Missing, duplicate, disconnected, stale-extra, or unconfirmed controller sessions remain visibly blocked. A same-session controller reload restores its server-held confirmation; a fresh session or authority restart requires confirmation again. Closed session identities age out of authority telemetry after a bounded 15-second retention window, allowing recovery from an accidental duplicate without a server restart; identities observed after the qualification clock starts remain part of that receipt. Insufficient RTT samples, excessive RTT, unstable identity, absent drive/fire challenge, absent reconnect, absent input-owner protection, incomplete duration, telemetry loss, or missing host attestations keep review eligibility false and remain named in the receipt.
compatibility/version contract: Qualification recorder 0.16.0; additive start-preflight schema v1; additive seat-confirmation schema v1; transport telemetry v1 with additive confirmation state/count; output qualification schema v1; controller/input/game authority contracts remain unchanged.
verification contract: Held-out ready/missing/duplicate/stale/unhealthy/unconfirmed preflight cases plus the existing 30-minute four-seat qualification, partial/attestation/duplicate-seat negatives, controller/screen confirmation authorization checks, same-session confirmation resume, server HTTP sender/receiver receipts, and live host/controller state transitions before and after four explicit confirmation gestures. Local clients remain explicitly non-physical evidence.
promotion gate: The recorder hand may be READY after deterministic, HTTP, and live local verification. `qa.physical-four-phone-lan` remains UNKNOWN until a representative 30-minute receipt is produced on the intended router, the host attestations are truthful, the physical devices are externally observed, and the appointed steward reviews the receipt.
```

`eligibleForStewardReview` is not a pass badge. A confirmation gesture says only that one controller session acknowledged its assigned seat; it cannot prove who tapped, that the client is a phone, or that the intended router is in use. The receipt deliberately fixes `physicalGateVerdict` to `requires-external-steward-review` because JavaScript cannot prove that four controller sessions came from four independent physical phones.
