# AXM HTML Live Builder Contract

Status: **EXPERIMENTAL / detached / not installed / not promoted / not canon**

## Purpose

Builder Mode is a small local authoring body on top of the same AXM native-web compiler used by the headless and human browser views.

```text
editable UTF-8 HTML draft
  -> Source Record
  -> tokenizer / Document Tree
  -> Page Model
  -> Structure Index
  -> Structure Layout / Display List
  -> inert AXM Structure Browser HTML
  -> sandboxed live preview
```

The builder does not introduce a second parser or a separate toy preview engine.

## Human workflow

Launch the local browser with:

```text
node cli.js serve-local <entry-file> --builder
```

The CLI prints the normal Browser Host receipt first and a separate HTML Builder Host receipt second. The builder receipt contains its loopback-only ephemeral URL.

The workspace contains:

- editable HTML source
- a 180 ms live-compile debounce
- explicit **Compile now** control
- Ctrl/Cmd + Enter compile shortcut
- Reset to the initial in-memory source
- bounded preview viewport width/height
- source and compile digests
- parser/compiler warnings
- sandboxed inert AXM preview

## Mutation boundary

The draft is **in memory only**.

Typing or compiling does not:

- write the source file
- mutate Browser Session navigation/history
- promote generated output
- install anything
- change canon

A future explicit save/export capability must be a separate authority and is not implied by Builder Mode.

## Active-content boundary

Source page behavior remains inert.

Builder compilation does not execute:

- page JavaScript
- Wasm
- forms
- service workers
- remote scripts/styles/images/media
- arbitrary network requests

The preview is generated by AXM's trusted Structure Browser renderer and displayed in a sandboxed iframe.

This means Builder Mode currently previews **AXM's semantic/structure rendering**, not full Chrome/Firefox CSS and Web Platform behavior.

## Transport boundary

The Builder Host:

- binds only to `127.0.0.1`
- uses a fresh random 24-byte capability path
- validates the exact Host header
- requires a present exact Origin on compile POSTs
- accepts JSON only for compile mutations
- enforces bounded request/source sizes
- uses no cookies or persistent browser storage
- exposes only its own `state` and `compile` routes
- performs no external network access

## Failure behavior

Malformed or partially typed HTML is handled by the existing bounded AXM parser. Parser warnings are surfaced in the workspace.

If compilation fails at a hard boundary, the request returns a typed failure and the previous successful preview remains available in the browser UI. The source file and Browser Session remain unchanged.

## Held follow-ups

Not implemented by this contract:

- explicit **Save to file** / **Save as** authority
- multi-file project editing
- CSS cascade / browser-layout parity
- page JavaScript execution
- external asset loading
- dev-server/HMR semantics
- git commit/push from the editor
- AI autonomous edits
- preview promotion into Browser Session history

Those should remain separate capabilities so editing, execution, network use, persistence, and promotion do not collapse into one hidden authority.
