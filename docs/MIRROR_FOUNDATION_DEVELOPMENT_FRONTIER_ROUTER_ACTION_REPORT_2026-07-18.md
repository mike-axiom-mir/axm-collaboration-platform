# Mirror Foundation-development frontier-router action report

Status: TEST generic proposal-only frontier routing, not CANON.

## Purpose

The automatic Foundation observer can preserve a new measured state and expose
holds or regressions, but observation alone cannot turn a gap into inspectable
next work. Hard-coding one hand per known dimension would also make Mirror
dependent on a steward adding each future route by name.

The frontier router is a generic bridge from measured non-passing dimensions
to typed development requests. It reads one verified observation snapshot and
its exact execution receipt, emits one request for every non-passing dimension,
and preserves the batch through the shared immutable store. It contains no
dimension-specific solution table and grants no request priority.

## Classification rule

- A measured hold becomes an `INDEPENDENT_EVIDENCE_ACQUISITION_REQUEST`.
- A measured regression becomes a `REGRESSION_INVESTIGATION_REQUEST` for an
  independently falsifiable cause-and-repair exam.
- An all-observed profile produces an explicit empty frontier rather than
  inventing work.

Regression requests expose changed source-file paths and changed top-level
evidence sections against the snapshots that recorded the regression. These
deltas are investigation inputs, not a cause claim or selected repair.

## Authority and limits

The router may write only private, content-addressed proposal traces. It has
zero evidence-fabrication, priority-selection, training-admission,
repair-selection, implementation-build, model-change, permission-grant,
runtime-promotion, canon-change, or world-action authority. Request order is
deterministic storage order, not ranking.

This closes one feedback-loop seam: measured unknowns now become inspectable
requests without a steward naming each dimension in router code. It does not
yet acquire evidence, design hands, choose organs, or prove that autonomous
growth is safe or complete.
