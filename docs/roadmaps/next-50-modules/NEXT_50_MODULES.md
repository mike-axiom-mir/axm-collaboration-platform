# AXM — next 50 most needed modules

Status: **50 ranked module foundations built and independently audited; commercial-product depth remains evidence-gated**. Version: **v1.1 — 19 July 2026**.

This list starts from the current Workshop, not the old five-card screenshot. AXM already has roughly seventy visible or integrated tool manifests, a governed twenty-module operations foundation, thirty-five creation hands, the PS2 Asset Forge, a versioned Living World service, controller transport, review, recovery, packaging, and explicit release gates. Those are not listed again under new names.

The ranking answered one question: **what should AXM build next to turn the local foundation into a repeatable PS2-floor → PS3 → PS4 game-production system without mandatory dependencies?** The first bounded foundation for every ranked module now exists. “Built” here means a discoverable contract, executable local scenario, independent verification, refusal boundaries, and a visible review surface—not a claim that fifty mature commercial products appeared at once.

## Permanent build rules

- AXM-native and offline first. No required cloud, CDN, paid service, proprietary runtime, or third-party package.
- A free/open-source adapter may be optional, isolated, digest-bound, replaceable, and absent without breaking the core route.
- Every module needs versioned inputs and outputs, exact provenance, bounded resource/failure behavior, deterministic recipes where meaningful, and an independent verifier.
- Generated candidates remain temporary until reviewed. Counts, labels, previews, syntax checks, and attractive screenshots do not promote quality.
- Human approval remains separate for appearance, listening, accessibility, rights, release, destructive change, and expanded authority.
- These modules attach to the five existing parents; they do not create another competing Hub, Forge, Library, or AI Team.

## Build order and exit gates

### P0 — playable 3D foundation (#1–10)

Build the runtime, round-trip bridge, core material/mesh/UV/LOD/rig kit, technical validator, modular environment system, and profiler as one vertical slice. The exit is not “ten modules exist.” The exit is one approved building, vehicle, and animated person running locally in a playable scene, matching authoring output, with import and performance receipts.

### P1 — PS3-capable content factory (#11–25)

Add reusable texture language, character/vehicle/world families, animation, effects, lighting, large-world compilation, and memory evidence. Exit only when a coherent district passes the independent technical validator, live performance budgets, and Mike's visual gate. Do not rename the Forge “PS3” before that evidence.

### P2 — complete game loop (#26–37)

Add player-facing UI, narrative, saves, networking, sessions, accessibility, visual/audio critique, automated play, balance evidence, AI regression tests, and consented datasets. Exit with one small but complete game that can start, play, pause, save, reconnect, finish, and be understood by a new user.

### P3 — independent production substrate (#38–44)

Build the dependency-replacement, codec, schema, scheduling, crash, merge, and security foundations underneath the vertical slice. These arrive after real blocked requests identify the exact primitives AXM needs; “replace everything” is not a bounded first build. Exit when the chosen production route has no mandatory runtime third-party package and failures remain reproducible.

### P4 — public release discipline (#45–50)

Add rights, reproducibility, size, marketplace certification, documentation, and localization. Exit with a rights-cleared package that rebuilds, installs, updates, rolls back, uninstalls, explains itself, and remains explicitly human-approved before publication.

## Why several obvious names are absent

- No separate **PS3 Asset Forge**: evolve the existing PS2 Asset Forge through the Create modules, keeping one source of truth.
- No second **Command Center**, **AI Team**, **Publish Library**, **Asset Vault**, **Review Queue**, **Recovery Center**, **World Server**, or **Controller Transport**: those already exist.
- No generic “AI image generator” entry: current creation hands and Studio already cover raster creation. The missing value is game-specific PBR, mesh, UV, rig, LOD, runtime, and perceptual-quality infrastructure.
- No required Blender, FFmpeg, Unreal, Unity, Git, cloud model, or commercial DCC module: optional free/open-source adapters may help verification, but the AXM route must remain usable without them.
