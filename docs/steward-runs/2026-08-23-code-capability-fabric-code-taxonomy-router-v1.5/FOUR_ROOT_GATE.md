# Four-root technical gate

Scope: v1.5 multi-axis code taxonomy and specialist-routing plan only.

This gate does not install, integrate, promote, publish, learn, execute a
candidate, authorize the repaired sandbox, or change `CANON`.

## 1. Truth — `PASS`

- A path yields mechanical language candidates, never semantic proof.
- Ambiguous, unknown, stale, forged, unsupported, and authority-expanding
  records remain visible holds or typed gaps.
- Declared capability, host observation, specialist route, generated candidate,
  executed evidence, accepted lesson, and installation remain separate states.
- The catalog says it is incomplete rather than claiming every language exists.

## 2. Agency / non-domination — `PASS`

- The planner grants no permission, network, provider, process, write, merge,
  lesson-admission, physical, or lifecycle authority.
- Multiple specialist contributions remain separate and cannot auto-merge.
- A root HOLD/FAIL stops classification; a profile cannot approve itself.
- Mike remains the final integration and merge gate.

## 3. Continuity — `PASS`

- Reuses deterministic-json-core and the existing portable-path validator.
- Reuses exact Specialist Library method masks rather than creating competing
  identities or general professional methods.
- Missing capability contracts route to the existing Hand Specification
  Foundry.
- All 27 Fabric selftests and the ten required Workshop checks pass.

## 4. Wisdom over speed — `PASS`

- Adds one inspectable planning rung, not a universal executor.
- Knowledge lanes remain empty and reference-only until a separate Tier-3 human
  decision and held-out regression evaluation.
- Physical actuation and experimental runtime execution remain outside scope.
- The existing 22 verifier warnings and remaining capabilities stay visible.

Human/integration outcome: `NOT_DECIDED`
