# Baseline Simulation Lab acceptance contract

Status: `TEST` design handoff for the expected later branch. It is not an
installed lab, permission grant, promotion decision or CANON change.

The lab should work with an arbitrary software baseline, Mirror baseline or
specialist-mask baseline by changing adapters, not by changing the truth rules.

## Required run envelope

Every run must bind:

1. an exact baseline capsule: subject kind, subject ID, version or commit,
   content digest, configuration digest, generated-view freshness and declared
   limitations;
2. the human direction or real need that justified the run;
3. the new information since the prior run;
4. the participating model or human seat IDs as provenance, never as proof;
5. the accepted input and output schemas for each adapter;
6. a time, storage, concurrency and retry budget;
7. output-availability checks for every later evidence dependency;
8. separate artifact and idea/evidence ancestry;
9. claim-specific proof routes, including live visual observation whenever a
   claim depends on appearance, layout, spatial state or motion;
10. one `axm.verified-capability-cycle-receipt/v1` result.

An unchanged baseline plus no new evidence, counterexample, requirement or
failure must return `NO_NEW_INFORMATION`. It must not spend another recursive
run merely to produce more agreement.

## Adapter boundary

The invariant cycle is:

```text
need -> gap -> source/provenance -> reuse/compose/adapt/build
     -> verify -> human hold/continue/reject -> governed availability -> refresh
```

Adapters may translate a software repository, Mirror state or specialist mask
into that cycle. They must preserve unsupported source fields, carry exact
source digests and refuse contract ambiguity. Adapter success does not claim
native schema identity.

## Required negative cases

- baseline commit or content digest changed;
- parent artifact missing, altered or beyond the declared depth;
- later evidence output removed, corrupted or replaced by a summary;
- sender and receiver digests disagree;
- declared PASS has no evidence or uses the wrong proof surface;
- semantic inspection is described as visual observation;
- permission declared but runtime denial/allow behavior disagrees;
- duplicate or circular handoff appears;
- resource limit, retry limit or worker bound is exceeded;
- candidate attempts execution, install, permission grant, promotion, CANON or
  root/Foundation mutation;
- candidate or model attempts to certify its own availability;
- free-text human comprehension is worse even if structured references are
  technically correct.

## Platform-specific acceptance

- A software adapter must bind Git identity and dirty worktree state separately.
- A Mirror adapter must keep original Mirror, private lessons and disposable
  challenger state distinct.
- A specialist-mask adapter must name the host model, mask version, allowed
  capabilities and evidence ceiling separately.
- Cross-model agreement is corroboration only. DeepSeek, OpenAI/ChatGPT/Codex,
  Claude Sonnet and Grok participation does not establish truth without the
  native verifier.

## Authority ceiling

The lab may return evidence, gaps, candidates and review packets. It may not
rewrite roots, change Foundation, install packages, grant permissions, promote
itself, mark itself CANON, train model weights, publish, push or make a public
release. Mike remains the human direction and merge gate.
