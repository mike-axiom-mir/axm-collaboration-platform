PORTABLE PROGRESSION SEAM
-------------------------
Circuitseed already stores one participant profile per occupied identity and has
conflict-safe profile export/import with recovery copies. This means progress is
not inherently owned by host player 1.

What does not exist yet is the complete phone handoff:
  phone-held profile -> join a friend's Hub -> explicit consent/import/bind ->
  play under that profile -> export/sync the updated profile back to the phone.

The active Game Hub seat record and phone join flow still need a stable profile_id
binding and consent UI. Until that is built and tested, cross-host phone
progression must not be claimed as working.

FUTURE SHARED-CONTROL SEAM
--------------------------
Xbox, PC and other physical controllers should become input adapters that emit
the same semantic action packets as phones, humans and connected AI. The research
is now captured as shared/controls/PHYSICAL_CONTROLLER_ROUTE.json plus a human-
readable route, a draft device-binding schema, proof gates and a 20/20 shared-
controls contract pass. The seat remains human while inputSource changes. The
runtime adapter and all physical hardware tests remain deliberately unimplemented;
no hardware-controller support is claimed by this record.

The local Discovery/Stance pass then found two concrete software seams: a valid
old phone could otherwise continue sending after a gamepad claim, and clearing
local input did not itself prove that the host received neutral state. Shared
Controls now has an optional opaque binding id plus monotonic source epoch,
rejects previous-source packets, preserves legacy phone-only packets, and can
transmit an immediate zero/released semantic packet. Raw device ids, accidental
claiming, non-standard mapping and hidden AI authority transitions are explicit
route controls. Shared Controls passes 23/23; physical hardware remains untested.
