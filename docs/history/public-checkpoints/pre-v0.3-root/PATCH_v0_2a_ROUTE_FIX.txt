AXM_WORKSHOP v0.2a ROUTE FIX

Changed:
1. Duo Test now routes through AXMConnect provider='bridge' and sends aiProvider='claude' or 'chatgpt' to the bridge.
2. Bridge v0.3 now understands opts.aiProvider / opts.targetProvider as the real AI behind the bridge.
3. START_AXM_FULL now starts the bridge even when no keys are set, so /health and honest no-key errors can be tested.
4. start-full.sh received the same no-key bridge-start behavior.

Why:
In v0.2, the Duo Test buttons used provider='claude' and provider='chatgpt'. AXMConnect interpreted that as a local connector provider name, but its registered providers are bridge/local/cloud. So the button could return noAI before reaching the bridge.

2. Open http://127.0.0.1:8787/health.
3. Open http://127.0.0.1:8788.
4. Open Duo Test.
5. With no keys: Ask Claude should produce honest provider claude has no key set.
6. With keys: Ask Claude / Ask ChatGPT / Ask BOTH / Relay should call the selected provider.
