AXM AI-TEAM COLLABORATION — STARTING RESEARCH
===============================================

Core loop:

ORIENT → CONTRACT → ALLOCATE → HAND OFF → WORK → CHALLENGE → VERIFY → MERGE → REVIEW → LEARN

AI-team collaboration is not several chat windows talking at once. It is a governed system of distinct identities, roles, task contracts, handoffs, shared artifacts, dissent, resource budgets, independent verification, recovery, and human authority.

Starting conclusions:

1. Identity, model, provider, role, tool access, private memory, and authority must remain separate. A model switch must not silently become an identity replacement or gain the former seat’s private context.

2. Teamwork needs structured tasks rather than conversational implication. Every delegated task should name scope, inputs, outputs, success criteria, evidence, budget, permissions, expiry, and refusal conditions.

3. Manager-style orchestration and peer handoffs are different. In a manager pattern, one coordinator retains control and calls specialists as tools. In a handoff pattern, another seat receives task ownership and relevant history. AXM should support both explicitly.

4. Handoff context requires filtering. Sending every previous message can leak private or irrelevant material, create context bloat, correlate errors, and weaken the receiving specialist’s independence.

5. Delivery is not acceptance. A task packet may be sent, validated, refused, accepted, started, completed, reviewed, and merged as separate states.

6. Contract-Net and related interaction protocols provide useful structures for calls for proposals, bids, refusal, acceptance, rejection, execution, and results. AXM should add stronger human authority, resource, privacy, evidence, and rollback boundaries around them.

7. Parallel teams work best when subproblems are genuinely separable. Multi-agent research can gain breadth through parallel specialists, but coordination cost and token use can rise sharply, and tightly dependent work may perform better through a smaller sequential team.

8. Agreement is not independent proof. Seats sharing the same source, prompt, model family, or copied reasoning can repeat one error and create false consensus.

9. Dissent should survive synthesis. Independent answers, challenger roles, contradiction maps, minority reports, and separate verifiers protect against silent consensus inflation.

10. Builder, judge, verifier, approval owner, and application owner should not collapse into one unchecked seat. A producing seat can provide tests but should not be the only authority deciding whether its work is correct.

11. Resource budgets must flow through delegation. Child tasks should not collectively exceed the parent token, time, tool, write, privacy, or risk envelope.

12. Multi-agent loops need finite turns, handoff depth, deadlines, non-progress detection, duplicate-work detection, backpressure, and emergency stop.

13. Human oversight must be documented and usable. Humans need enough information about system limits, outputs, risks, and current state to make real decisions rather than rubber-stamp opaque team activity.

14. Private identity memory should never be copied merely because two AI seats collaborate. Shared wisdom should be explicit, source-linked, scoped, reviewable, and revocable where appropriate.

15. Process learning should create candidate patterns, not automatic canon. After-action reviews can improve routing, task shapes, and collaboration protocols while Mike remains Merge Gate.

CURRENT AXM ROOTS TO PRESERVE
=============================

AXM already has meaningful AI-team organs:

- Agent Command Center v0.4 is the identity and connector control plane for local and connected AI identities. It enforces private memory boundaries, connector/model locks, optional default selection, and explicit shared wisdom.
- AI Task & Talk Room v0.1 is the collaboration and tasks view. Automatic dispatch and auto-talk are local-model-only with persistent explicit opt-in/out and one-click stop; sensitive tasks can use a human review gate; nothing becomes wisdom automatically.
- Supervised Local Duo v3 lets two local AI identities work independently or through visible attributed relay under Mike and Axiom/Mir supervision, without copying private identity memory.
- Reasoning Shell is explicitly branch-only, not CANON or foundation; it proposes profile-driven step loops, human checkpoints, session logs, after-action reviews, and tweaks that are never auto-applied.
- Shell Guardian is an always-armed circuit breaker. Red triggers deny tool calls, preserve evidence, trip visibly, and stop affected process trees; its classification does not claim to prove intent.
- Technical Glasses recompiles live read-only technical ground truth from manifests, contracts, readiness, fingerprints, and tests. Its review candidates are evidence for Mike, never approval, promotion, CANON, or blanket runtime proof.
- ChatGPT/Codex and Claude connectors are background services surfaced through AI Team. They preserve separate lanes, manual/proposal-only boundaries, local status proof, user-settings boundaries, and no hidden memory merge.
- AXM’s wider architecture already uses Mike as Merge Gate, proposal-first meaningful AI action, shared gates for humans and AI, source verification, and append-only correction.

The 100 seeds below should connect and strengthen these roots rather than replace AI Team, Agent Command Center, Task & Talk, Duo Test, Reasoning Shell, Shell Guardian, Technical Glasses, connectors, Review Inbox, Verification Spine, Evidence Desk, or Merge Gate.

AXM GAP AND INTEGRATION NOTES
=============================

Preserve:

- stable AI identities and model/provider locks;
- private identity memory separation;
- explicit shared wisdom only;
- local-model-only automatic dispatch where enabled;
- one-click stop and persistent opt-in/out;
- proposal-first meaningful AI action;
- human and AI use the same gates;
- Mike as Merge Gate;
- Technical Glasses as read-only ground truth;
- Shell Guardian as circuit breaker, not intention detector;
- connectors as bounded services rather than hidden authority;
- branch-only experiments remain branch-only until evidence.

1. Team identity, roles, capabilities, authority, and private boundaries
------------------------------------------------------------------------
1. axm.team.member-descriptor — AI Team Member Descriptor
   Describe one human, AI, tool, or service seat through stable identity, provider/model binding, role, capabilities, limitations, availability, and authority boundaries.
2. axm.team.identity-provider-lock — Identity, Model, and Provider Lock
   Bind a named AI identity to its approved local or connected model/provider route and visibly block silent substitution.
3. axm.team.role-capability-matrix — Role and Capability Matrix
   Map Scout, Builder, Tester, Repairer, Verifier, Steward, Challenger, Human, and specialist roles to exact capabilities and prohibitions.
4. axm.team.authority-lease — Team Authority Lease
   Grant a seat one exact task, tool set, target, duration, write boundary, and revocation state without inheriting broader team authority.
5. axm.team.private-memory-boundary — Private Identity Memory Boundary
   Keep each seat’s private identity memory separate while allowing explicit source-linked shared context and wisdom packets.
6. axm.team.shared-wisdom-envelope — Explicit Shared Wisdom Envelope
   Transfer reviewed reusable lessons between seats with source, limits, dissent, expiry, and no automatic private-memory copying.
7. axm.team.tool-capability-allowlist — Team Tool and Capability Allowlist
   Expose only task-relevant tools, operations, files, connectors, and permissions to each seat.
8. axm.team.model-provider-provenance — Model and Provider Provenance Receipt
   Record which model, version, provider, connector, configuration, and runtime produced each proposal or artifact.
9. axm.team.presence-availability-lease — Presence and Availability Lease
   Report whether a seat is connected, ready, busy, degraded, blocked, paused, or absent without assuming continued availability.
10. axm.team.topology-authority-map — Team Topology and Authority Map
   Visualize seats, managers, peers, tools, handoff routes, write owners, review gates, and emergency-stop boundaries.
