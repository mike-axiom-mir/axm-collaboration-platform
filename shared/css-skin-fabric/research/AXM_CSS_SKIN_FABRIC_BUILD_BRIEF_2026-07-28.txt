AXM CSS SKIN FABRIC v0.1 — IMPLEMENTATION HANDOFF
Date: 2026-07-28
Language: English

MISSION
Turn the existing AXM visual layer into a modular, reusable, themeable, testable CSS Skin Fabric without redesigning or rebuilding the current platform from scratch.

ROOT RULES
- Preserve current behavior and current visible output first.
- No silent rewrite.
- No destructive migration.
- Create rollback/checkpoint before changes.
- Native CSS is the source of truth.
- Existing framework may be adapted, but must not become the design root.
- Every new visual abstraction needs a contract, source lineage, tests, fallback, and docs.
- Generator output is candidate-only until human review.
- Accessibility and performance are part of visual quality, not later add-ons.

FIRST REQUIRED ACTION: SOURCE AUDIT
1. Find every CSS/SCSS/module/style entry point.
2. Find inline styles and runtime style injection.
3. Identify UI framework or component library.
4. Count and map raw colors, spacing values, radii, shadows, z-index values, animation durations, and breakpoints.
5. Find all !important declarations and selector-specificity hotspots.
6. Capture baseline screenshots for all routes and major states.
7. Record current browser targets and minimum supported devices.
8. Produce AUDIT_REPORT.md before migration.

MIGRATION RULE
- Place current styles into the legacy layer or a legacy adapter without changing screenshots.
- Ensure all new author CSS is in a named layer.
- Put imported third-party styles in vendor.
- Keep overrides small, documented, and test-covered.
- Never add an untracked !important.

AXM-SPECIFIC LINT RULES
- No ID selectors in component CSS.
- Limit selector depth.
- Ban transition: all.
- Ban raw colors in component files.
- Ban raw z-index outside depth tokens.
- Ban unapproved !important.
- Require approved layer context.
- Require motion tokens for durations/easing.
- Flag unsupported/experimental features unless wrapped in documented progressive enhancement.

PERFORMANCE RULES
- Prefer transform and opacity for animation.
- Measure any animated layout, shadow, filter, blur, mask, or clip-path.
- Limit simultaneous backdrop filters.
- Provide minimal, balanced, and cinematic effect modes.
- Test on the lowest supported device profile.
- Use aspect-ratio/dimensions to avoid layout shift.
- Avoid permanent will-change.
- Remove unused CSS.

ACCESSIBILITY RULES
- WCAG 2.2 AA target.
- Normal text usually >= 4.5:1.
- Large text and meaningful non-text UI indicators >= 3:1 where applicable.
- Clearly visible focus.
- Target size >= 24x24 CSS px or compliant spacing exception; prefer larger.
- No hover-only operation or meaning.
- Reduced-motion support.
- Forced-colors support.
- No state conveyed only by color.
- Preserve content and function at zoom and altered text spacing.

FEATURE POLICY — JULY 2026
CORE/COMMON:
- Flexbox, Grid, Subgrid
- Custom properties
- @layer
- Container size queries
- clamp(), aspect-ratio
- :where(), :is(), :has()
- color-mix()
- masks, clip-path, filters and blend modes with measurement

MODERN WITH FALLBACK:
- @property
- @scope
- newer text-wrap behavior

PROGRESSIVE ENHANCEMENT:
- View Transitions
- anchor positioning
- scroll-driven animation
- CSS custom functions

DO NOT MAKE THE ROOT:
- Native CSS mixins: not broadly/browser supported.
- CSS Painting API: limited/experimental.

GENERATOR STUB
Build a candidate-only mold generator that:
1. Reads approved token and recipe schemas.
2. Generates only values inside declared ranges.
3. Produces CSS + manifest + specimen HTML.
4. Runs lint, screenshots, overflow, accessibility, compatibility, and performance checks.
5. Rejects duplicate or near-duplicate candidates.
6. Creates a review packet.
7. Never writes directly into canonical recipes.
8. Creates rollback data before promotion.
9. Respects one-version-per-day promotion policy.

ACCEPTANCE CRITERIA FOR v0.1
- Existing baseline screenshots still match before intentional redesign.
- Layer order is active and documented.
- Current CSS is isolated as legacy.
- Tokens exist in one machine-readable source and generated CSS.
- Ten layout primitives work independently.
- Ten core components show all states in a local specimen gallery.
- Eight effect recipes have manifests and fallbacks.
- At least three themes remap components without structural CSS copies.
- Stylelint passes.
- Playwright visual comparisons pass in Chromium, Firefox, and WebKit projects.
- Reduced-motion and keyboard-focus fixtures pass.
- Performance modes work.
- Migration log, source map, rollback pointer, and honest limitations are included.
