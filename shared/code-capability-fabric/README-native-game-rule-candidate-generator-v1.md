# Native Game-Rule Candidate Generator v1.4

Status: `TEST`

This bounded rung turns the exact v1.2 Atlas-backed game-rule application plan
into one byte-bound JavaScript candidate bundle **in memory**. It is a narrow
native recipe for the declared `FILTER_VALUES` then `MAP_VALUES` game-rule
shape, not a general code generator or executor.

The generator mechanically rebuilds the plan from the installed Foundry
catalog, checks the two requester-declared recipe-to-step mappings, binds a new
Tier-1 grounded-consent scope, and independently emits a nine-file module
bundle. The bundle contains a pure rule function, closed input/output schemas,
an application record, an inert candidate receipt, and all-`UNRUN` tests.

Atlas snippet bytes remain absent, unapplied, and unexecuted. The implementation
is native code produced from the typed operation contract; it does not copy the
referenced snippets. Both Atlas and generated candidate source remain
`RESEARCH_ONLY_HOLD` with direct reuse disabled until Mike decides otherwise.

The returned packet is `EXPERIMENTAL`, unmaterialized, uninstalled, and grants
no permission, network, provider, workspace, or lifecycle authority. It does
not authenticate the natural person behind the request. Its next gate is an
authenticated decision over the exact candidate bytes before any Detached
Candidate Nursery write. Runtime, correctness, safety, visual quality, and
gameplay remain unproven because candidate code and candidate tests are not run.

Run:

```powershell
node shared/code-capability-fabric/selftest-native-game-rule-candidate-generator-v1.js
```
