# Code Specialist → Organ Intent Adapter v1 (TEST)

This is the first exact bridge from the Code Capability Fabric's v1.5
classification/specialist lanes into the canonical Deterministic Organ Fabric.
It does not turn a filename or specialist profile into code behavior.

The adapter accepts one byte-bound v1.5 specialization request and plan, one
exact artifact/specialist-lane selection, the canonical
`software-workshop@1.1.0` field-pack reference, and an explicit human-authored
typed intent draft. It deterministically appends the selected specialist's
profile digest, empty knowledge-lane state, evidence ceiling, and refusal list,
then seals an `axm.organ-intent/v1` with `status: EXPERIMENTAL` and
`authority: NONE`.

The ready result means only: **the exact intent is ready for human review before
a separate Organ Fabric generation request**. It does not compile an organ,
generate an organ package, execute generated material, run tests, load
knowledge, write the Workshop, install, integrate, publish, promote, or CANON.

Only the verification-route field pack is supported in this rung because that
is the current canonical software field pack. HTML, CSS, JavaScript, schemas,
tests, shaders, audio, and other specialist lanes are routing context; their
profiles remain TEST and are not implementation or capability proof. A future
implementation-organ field pack needs its own reviewed contract and evidence.

This means the Code Atlas/specialist catalog is now wired into creation
planning as exact lineage and refusal context, not treated as a bag of hidden
"cheat codes." Domain knowledge can be attached later only through a separate
versioned knowledge-lane contract with its own rights, evidence, and human
decision.

Root `HOLD`/`FAIL` stops before specialist-plan rebuild. With passing roots, a
stale, forged, held, ambiguous, permission-expanding, or non-exact v1.5 plan
fails closed. Multiple specialist lanes are preserved; the caller must name one
exact lane, and the adapter records that no automatic merge occurred.
