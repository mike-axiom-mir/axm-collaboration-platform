WHY THIS BRANCH EXISTS
----------------------
AXM's code, systems thinking, collaboration architecture, and modular growth
have advanced faster than its visual layer.

The missing layer was described as:
- reusable creative molds;
- skins and materials;
- organs that can create or modify visual structure;
- systems that generate more molds;
- a way to preserve the intelligence behind successful visuals rather than
  repeatedly asking an AI or human to rediscover it.

The goal is not merely to collect many templates. The goal is to build a
visual capability layer between intent and rendered output.

CORE CONCLUSION
---------------
AXM does need a substantial mold library, but it should not become a huge flat
folder containing thousands of almost identical files.

AXM needs two connected systems:

1. A strong starter library of reusable tokens, organs, molds, themes, presets,
   validators, and adapters.
2. A Mold Foundry that can extract, derive, test, preview, organize, and grow
   more molds without silently rewriting their parents.

The correct working definition is:

VISUAL MOLD =
protected structure
+ typed controls
+ content slots
+ variant axes
+ reusable organs
+ state logic
+ validation
+ provenance
+ lineage
+ export adapters

The important design shift is:

Do not store only the finished result.
Store the visual reasoning that can safely regenerate related results.

VISUAL TEMPLATE CAPABILITY LEVELS
---------------------------------
LEVEL 0 — Snapshot
One finished result.

LEVEL 1 — Editable layout
Replaceable text and images.

LEVEL 2 — Parameterized component
Typed controls and safe ranges.

LEVEL 3 — Variant family
Themes, formats, states, and inherited alternatives.

LEVEL 4 — Procedural mold
A graph generates geometry, materials, lighting, effects, or layout.

LEVEL 5 — Behavioral mold
States and external data drive the visuals.

LEVEL 6 — Composable ecosystem
Molds contain and reference other molds.

LEVEL 7 — Meta-mold / Foundry
A governed system proposes and validates new molds.

Most ordinary template libraries stop around Levels 1–3.
AXM should support Levels 2–7 while keeping simple use easy.

RESEARCH CONVERGENCE
--------------------
The strongest existing systems use different names, but converge on the same
architecture.

1. PROTECTED CORE + EXPOSED CONTROLS
------------------------------------
Figma components distinguish internal structure from intended change points.
Useful controls include:
- text;
- booleans;
- instance swaps;
- slots;
- variants;
- exposed nested properties.

Canva brand templates similarly allow identity-critical elements to remain
locked while editable fields stay available. Data Autofill and Bulk Create
turn one template into many consistent outputs.

Adobe Motion Graphics Templates package animation, media, and dependencies
while exposing selected text, color, media, layout, and data controls.

AXM SHOULD USE THREE FREEDOM LEVELS:

PROTECTED
Cannot change without creating a derived mold.
Examples:
- brand safe area;
- semantic reading order;
- mandatory accessibility structure;
- provenance fields.

CONSTRAINED
Can change inside declared boundaries.
Examples:
- glow intensity 0.0–0.65;
- title up to 70 characters;
- blur within a performance budget.

FREE
Replaceable content or creative extension.
Examples:
- image slot;
- optional decoration;
- custom scene object.

This prevents both:
- templates so rigid that they kill creativity;
- unrestricted files that break easily.

2. TOKENS, NOT SCATTERED VALUES
-------------------------------
Design-token systems store decisions such as:
- color;
- typography;
- spacing;
- dimensions;
- timing;
- easing;
- gradients;
- borders;
- shadows;
- material and motion values.

Godot themes show the same principle through cascading runtime UI values.

Instead of hard-coding every button:

background = #111827
glow = 22px
corner radius = 16px

Use semantic bindings:

button.background = surface.deep
button.glow = energy.medium
button.radius = shape.soft

Then themes such as:
- Aetherglass;
- Paper Neon;
- Rooted Machine;
- Public Calm;
can redefine the decisions centrally.

3. COMPLEX GRAPH, SIMPLE USE INTERFACE
--------------------------------------
Houdini Digital Assets package a node graph, files, parameters, and a custom
public interface into a reusable asset.

Blender node groups make shader, geometry, and compositor graphs reusable and
composable.

ComfyUI reusable subgraphs and App mode can hide a complex workflow behind a
small set of inputs and outputs.

AXM SHOULD RETAIN TWO INTERFACES:

WORKSHOP INTERFACE
The full graph, dependencies, validators, and advanced controls for builders
and AI collaborators.

USE INTERFACE
A small understandable control panel for ordinary users.

A sophisticated lighting or image-generation mold should be usable through a
few meaningful controls without requiring knowledge of shaders, samplers,
node graphs, or render pipelines.

4. VARIANT INHERITANCE, NOT COPY EXPLOSION
------------------------------------------
OpenUSD VariantSets preserve non-destructive alternatives such as:
- material;
- model;
- detail level;
- configuration.

Unity Prefab Variants and Material Variants inherit from a parent and store
only overrides.

Unreal Material Instances use parameterized parent materials and change
selected values without duplicating the full graph.

7. PORTABLE SCENE AND MATERIAL ADAPTERS
---------------------------------------
MaterialX provides platform-independent material and look descriptions across
supporting tools.

OpenUSD supports composed scenes, layering, references, and non-destructive
variants.

glTF supports runtime delivery and material extensions.

Unreal's procedural content systems demonstrate graph-based creation from
asset utilities to buildings, biomes, and worlds.

No one format covers:
- UI;
- marketing graphics;
- game assets;
- materials;
- VFX;
- AI workflows;
- scenes;
- worlds;
- responsive layouts.

AXM therefore needs one semantic contract with multiple adapters rather than
forcing every visual medium into one proprietary file.

MINIMUM MOLD CONTRACT
---------------------
A readable mold manifest should include at least:

{
  "schema": "axm.visual-mold/0.1",
  "id": "axm.marketing.cinematic-service-card",
  "name": "AXM Cinematic Service Card",
  "version": "0.1.0",

  "lineage": {
    "parent": null,
    "derived_from": [],
    "change_policy": "explicit-approval"
  },

  "core": {
    "protected": [
      "layout.reading_order",
      "brand.safe_area",
      "accessibility.semantic_structure"
    ]
  },

  "inputs": {
    "title": {
      "type": "text",
      "maximum_characters": 70
    },
    "message": {
      "type": "text",
      "maximum_characters": 320
    },
    "theme": {
      "type": "enum",
      "values": [
        "aetherglass-dark",
        "aetherglass-light",
        "public-calm"
      ],
      "default": "aetherglass-dark"
    },
    "media": {
      "type": "slot",
      "accepts": ["image", "video", "generated-scene"],
      "minimum": 1,
      "maximum": 1
    },
    "cinematic_energy": {
      "type": "number",
      "minimum": 0,
      "maximum": 1,
      "default": 0.45
    },
    "glow_density": {
      "type": "number",
      "minimum": 0,
      "maximum": 0.8,
      "default": 0.25
    }
  },

  "variants": {
    "format": ["square", "portrait", "landscape", "phone"],
    "motion": ["still", "ambient", "cinematic"],
    "performance": ["low", "standard", "ultra"]
  },

  "organs": [
    "axm.layout.responsive-focus",
    "axm.surface.aetherglass",
    "axm.light.cinematic-depth",
    "axm.motion.ambient-energy"
  ],

  "checks": [
    "text-overflow",
    "minimum-contrast",
    "safe-area",
    "missing-font",
    "missing-dependency",
    "rights-and-provenance",
    "performance-budget",
    "reduced-motion"
  ],

  "outputs": [
    "png",
    "svg",
    "html",
    "video",
    "rive"
  ]
}

In plain language:
- Core defines what may not silently change.
- Inputs are understandable controls.
- Variants describe independent choices.
- Organs perform complex work.
- Checks stop broken or unsafe results.
- Outputs identify compatible adapters.

Large graphs, textures, models, and source files should be referenced as
dependencies instead of embedded into one unreadable manifest.

19. AXM MOLD FOUNDRY
--------------------

1. Add finished visual and source files.
2. Mark what must remain protected.
3. Mark what should be replaceable.
4. Detect repeated colors, spacing, materials, and effects.
5. Suggest reusable organs.
6. Suggest useful controls.
7. Generate controlled variants.
8. Test where the design breaks.
9. Create a manifest.
10. Generate proof sheets.
11. Save as candidate.

- proof sheets;

A strong set of reusable organs can be more valuable than thousands of static
templates.

FAILURE MODES AND REPAIRS
=========================

VARIANT EXPLOSION
Problem:
Every combination becomes a separate file.

Repair:
- independent variant axes;
- inheritance;
- generated previews;
- sparse overrides.

DEPENDENCY DECAY
Problem:
Fonts, plugins, models, nodes, shaders, or textures disappear.

Repair:
- dependency manifest;
- hashes;
- compatible substitutes;
- bundled public-safe fallback;
- degraded mode.

OVER-LOCKING
Problem:
The mold becomes a rigid form.

Repair:
- permanent locks only for identity, integrity, safety, consent, provenance,
  and accessibility;
- constrained ranges elsewhere.

CROSS-ENGINE FALSE EQUIVALENCE
Problem:
CSS glow, Blender shader, Godot shader, and Unreal material do not render
identically.

Repair:
Use semantic concepts such as:
energy.edge_glow.medium

Each adapter produces its closest validated implementation.
Never promise pixel-identical cross-engine output.

AI NONDETERMINISM
Problem:
Work cannot be reproduced because model, seed, sampler, references, or repair
steps are missing.

Repair:
Record the full generation packet.
Label results:
- reproducible;
- approximately reproducible;
- exploratory.

BEAUTIFUL BUT UNUSABLE EFFECTS
Problem:
Blur, glow, particles, glass, or lighting hurt readability or weak devices.

Repair:
- low/standard/ultra implementation;
- reduced motion;
- text protection;
- performance budgets;
- fallback visuals.

RIGHTS AND SOURCE LOSS
Problem:
Restricted fonts, logos, stock, likenesses, or generated assets spread without
clear permission.

Repair:
Store:
- source;
- author;
- license;
- consent;
- transformation history;
- redistribution state;
- public/private scope.
