## v0.9.1 — Local intake hardening

- storage failures throw and governed transactions roll back instead of logging false success;
- current workspace, family, project, batch, safety-capsule, and rescue packets require valid integrity;
- snapshots and project revisions verify before restore;
- approved project/batch archives retain `ARCHIVED`, and inactive dependencies block approval;
- batch intake rejects over-limit, ragged, or oversized-cell data without silent truncation;
- header normalization preserves explicit collision renames and distinct values;
- port 8765 is stable, with reuse-or-refuse behavior, a local Host allowlist, and exact manifest coverage;
- quarantined theme previews use validated declarative values only;
- mobile, light-theme, keyboard, focus-preview, and dialog accessibility were improved.

FNV-1a-32 remains non-cryptographic, collision-prone accidental-corruption evidence only. Windows Chrome/Edge visual inspection and downstream target-engine parity remain **LOCAL VALIDATION REQUIRED**.

## Root continuity

Across all versions, the protected direction remained unchanged:

- local-first;
- no telemetry;
- no hidden approval or activation;
- no silent parent mutation;
- no automatic canon merge;
- no cryptographic-authenticity claim from packet fingerprints;
- no durable-backup claim for browser storage;
- no target-engine parity claim without target-tool validation.
