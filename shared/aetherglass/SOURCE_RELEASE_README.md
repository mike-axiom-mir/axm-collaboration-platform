# AXM Aetherglass Visual Engine v7.1.0

A local-first, dependency-free visual-world, luminous-layer, production, authoring, Storycraft, and offline Product Design system for AXM-style platforms.

v7.1 adds one bounded visual organ instead of rebuilding the engine: Luminous Layer Forge. Six optional light planes can now deepen the existing Aetherglass world while the v7 reliability, accessibility, ownership, and rollback repairs remain intact. The release also includes an original offline Product Design workflow for local human/AI collaboration.

## Start

Extract the ZIP and open START_HERE.html. The full offline studio is demo/index.html.

On Windows, double-click START_LOCAL_PRODUCT_DESIGN_WORKFLOW.bat to start a local five-gate design run. The command-line route is `python tools/local_product_design.py start`.

For intake, preserve a rollback first, mount the core, add optional organs one at a time, and run the target platform’s own accessibility, performance, lifecycle, and visual-regression checks.

## New in v7.1

- Luminous Layer Forge provides halo, crown, aurora, prism, caustic, and refraction planes.
- Five authored visual presets plus Off: Quiet Aura, Sovereign Aurora, Prismatic Cathedral, Neon Sanctum, and Event Horizon.
- Intensity, depth, individual-layer, and reactive focal-light controls remain optional and reversible.
- Low quality, transparency-off, and high-contrast routes automatically shed expensive or distracting planes.
- Reduced/off motion keeps the light composition static; capture freeze and print routes stop or remove decorative layers.
- Finite focal radiance nodes are owned, timed, and removed on destroy.
- The studio exposes the full light stack without replacing existing scene, cue, surface, or lighting systems.
- The local Product Design workflow creates context, visual-target, build, visual-QA, and handoff gates with source fingerprints, explicit approval, evidence requirements, and reversible reopening.

## Preserved v7 hardening

- Runtime stress now restores its snapshot without cancelling its own successful run.
- Palette state participates in config export, persistence, reset, and rollback.
- All nineteen Design Token Forge fields route to variables used by the live visual system.
- Quality, contrast, and production budgets no longer create self-referential CSS custom-property cycles.
- Journey dwell time stays readable under reduced/off motion; motion preferences change transitions, not reading time.
- Decorative interaction, focus, and lighting effects honor reduced/off motion.
- Lighting pulses and sweeps are tracked and removed on destroy; fixed coordinates preserve valid zero values.
- Focus narration has a polite live region while the visual frame remains hidden from assistive technology.
- Capture readiness requires zero running animations when animation state can be observed.
- Built-in workbench transitions and cues are validated before application.
- The studio has real section links, a persistent small-screen mode rail, manual journey playback by default, larger text floors, and repaired mobile action sizing.
- Dynamic demo copy is built with DOM text nodes instead of HTML string injection.

## Boundaries

- Local only; no runtime network primitives or telemetry
- No arbitrary code execution from presets, tokens, contracts, blueprints, cues, or journeys
- No content-meaning read, emotional inference, automatic interface rewrite, or navigation takeover
- Explicit approval before authoring, focus, journey, or capture mutations
- Capture Studio prepares a frame; it does not take, save, or upload a screenshot
- Finite tests and DOM counts do not prove long-session browser/GPU memory safety
- The standalone demo is not represented as already integrated into a live AXM platform
