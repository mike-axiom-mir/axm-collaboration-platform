# Holodeck roadmap

## H0 — canonical atom (`TEST`)

- Versioned world, deck-plan, intent, state, sensory-frame, and snapshot contracts.
- Deterministic compiler and digest.
- Identical human-machine intent path.
- Primitive WebGL Screen Deck.
- One interaction-complete example: Echo Atrium.

## H1 — richer Screen Deck

- Versioned asset references and material/lighting profiles.
- Animation and audio adapters.
- Better collision and navigation meshes.
- Story/rule graph adapter and multiple connected spaces.
- Explicit import routes from Spatial Studio and Game Forge.

## H2 — embodied simulation

- VR and AR adapters consuming the same deck plan.
- Spatial audio, tracked controllers, accessibility profiles, and comfort modes.
- Visual sensor adapter with real pixel/frame evidence alongside the structured state sensor.
- Governed shared-world authority through a versioned Living World adapter.

## H3 — fabrication and robotics

- Static geometry/material selections compiled into fabrication candidates.
- World intents translated into permission-gated robot plans.
- Physical safety, reachability, collision, emergency stop, and independent authorization evidence.

## Horizon — physical-space manipulation

Future display, haptic, environmental, or matter-manipulation systems may implement `axm.holodeck-render-adapter/v1` or a successor. No current software milestone claims those substrates exist. Canonical world meaning must remain independent from every temporary output technology.
